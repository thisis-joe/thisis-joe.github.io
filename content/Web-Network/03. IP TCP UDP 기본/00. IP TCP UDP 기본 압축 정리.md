# IP / TCP / UDP 기본

### 3줄 요약
- IP는 목적지까지 패킷을 보내는 주소 체계이고 TCP/UDP는 애플리케이션 간 전송 방식을 제공한다.
- TCP는 연결, 순서, 재전송을 제공하지만 지연과 상태 비용이 있고 UDP는 가볍지만 신뢰성을 애플리케이션이나 상위 프로토콜이 맡는다.
- 백엔드는 port, listener, firewall, connection state를 이해해야 connection refused와 timeout을 구분할 수 있다.

### 핵심 정리
- IP와 port를 합쳐 socket endpoint를 이룬다. 웹 서버가 떠 있다는 말은 특정 IP/port에서 listener가 있다는 뜻이다.
- TCP 연결 실패는 `connection refused`, `timeout`, `reset`으로 나뉘며 각각 리스너 없음, 경로/방화벽, 연결 중단처럼 의미가 다르다.
- UDP는 DNS, QUIC, 일부 streaming에서 중요하다. HTTP/3는 QUIC 위에서 동작하므로 UDP가 웹 성능과도 연결된다.
- NAT, ephemeral port, TIME_WAIT 같은 OS 자원은 대량 outbound 호출에서 병목이 될 수 있다.

### 헷갈리는 지점
- IP가 열려 있으면 서비스도 열린 것이라고 생각하기 쉽다. 실제 서비스는 port listener가 필요하기 때문이다.
	- 핵심 판단 포인트는 IP 도달성과 TCP port 수신을 분리한다.
- timeout과 connection refused를 같은 장애로 묶기 쉽다. 둘 다 접속 실패처럼 보이기 때문이다.
	- 핵심 판단 포인트는 거절은 응답이 온 것이고 timeout은 응답이 오지 않은 것이다.
- UDP는 웹 백엔드와 무관하다고 느끼기 쉽다. 그러나 DNS와 HTTP/3/QUIC이 UDP 기반이다.
	- 핵심 판단 포인트는 서비스 경로에서 UDP가 쓰이는 구간을 확인한다.

### 확인 질문
- connection refused와 timeout의 차이는 무엇인가?
	- refused는 대상이 연결을 거절한 것이고 timeout은 응답이 돌아오지 않은 것이다.
- 백엔드에서 port와 listener를 확인해야 하는 이유는 무엇인가?
	- LB나 proxy가 전달하는 port와 애플리케이션이 실제로 듣는 port가 어긋나면 502/503이 발생하기 때문이다.
- UDP가 웹 개발에서 중요한 대표 사례는 무엇인가?
	- DNS와 HTTP/3의 QUIC이다.

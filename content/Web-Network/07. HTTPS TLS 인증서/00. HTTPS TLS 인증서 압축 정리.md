# HTTPS / TLS / 인증서

### 3줄 요약
- HTTPS는 HTTP를 TLS 위에서 보호하는 방식이고 인증서로 서버 신원을 검증한다.
- TLS 문제는 공개 인증서뿐 아니라 인증서 체인, SNI, termination 위치, backend TLS, 갱신 자동화에서 자주 발생한다.
- 백엔드는 인증서 오류를 브라우저 화면으로만 보지 말고 `openssl s_client`로 handshake와 chain을 확인해야 한다.

### 핵심 정리
- TLS handshake는 버전, cipher, 인증서, SNI, 키 교환을 협상한다.
- 인증서는 도메인 소유와 서버 신원을 검증한다. SAN에 접속 도메인이 없거나 중간 인증서가 빠지면 실패한다.
- TLS termination이 LB나 proxy에서 일어나면 Client-to-LB와 LB-to-App 보안 경계를 따로 봐야 한다.
- mTLS는 서버뿐 아니라 클라이언트 인증서도 검증해 내부 서비스 보안에 쓰인다.

### 헷갈리는 지점
- 인증서가 있으면 TLS는 끝났다고 생각하기 쉽다.
	- 핵심 판단 포인트는 chain, SAN, SNI, trusted root, 만료, 갱신이 모두 맞아야 한다.
- 공개 구간 TLS만 보면 된다고 생각하기 쉽다.
	- 핵심 판단 포인트는 Gateway와 backend 사이 TLS가 따로 실패할 수 있다.
- HTTPS termination 위치를 몰라도 된다고 생각하기 쉽다.
	- 핵심 판단 포인트는 scheme, secure cookie, redirect, client IP 판단에 직접 영향이 있다.

### 확인 질문
- SNI가 중요한 이유는 무엇인가?
	- 같은 IP에서 여러 인증서를 제공할 때 클라이언트가 접속하려는 hostname을 알려 주기 때문이다.
- TLS termination 위치가 백엔드에 영향을 주는 이유는 무엇인가?
	- 앱은 실제 요청 scheme과 client IP를 forwarded header로 받아 판단하기 때문이다.
- 인증서 chain 문제가 무엇인가?
	- 서버 인증서와 신뢰된 root 사이의 중간 인증서가 누락되거나 잘못되어 검증에 실패하는 문제다.

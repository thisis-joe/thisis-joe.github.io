> [!summary]  
> DP는 **작은 문제의 결과를 저장해두고, 큰 문제를 그 결과로 해결하는 방식**이다.  
> 코딩테스트에서는 보통 `경우의 수`, `최댓값`, `최솟값`, `가능 여부` 문제에서 사용한다.
> 
> |DP를 의심할 상황|예시|
> |---|---|
> |같은 계산이 반복됨|피보나치, 계단 오르기|
> |이전 결과로 현재 값을 구함|`dp[i] = dp[i-1] + dp[i-2]`|
> |경우의 수를 세야 함|타일링, 조합, 경로 개수|
> |최댓값/최솟값을 구해야 함|배낭, 정수 삼각형, 경로 최댓값|
> |선택 제한 조건이 있음|연속 선택 금지, 이전 색과 달라야 함|
> 
> DP의 핵심 조건:
> 
> ```text
> 1. 중복 부분 문제
>    같은 작은 문제가 여러 번 반복해서 등장함
> 
> 2. 최적 부분 구조
>    큰 문제의 답을 작은 문제의 답으로 만들 수 있음
> ```
> 
> 경우의 수 문제도 결국 작은 경우의 수를 더해서 큰 경우의 수를 만들 수 있으면 DP로 풀 수 있다.

## 1. DP로 풀 수 있는 구조

> [!info]  
> DP를 쓸 수 있는지 보려면 “이전 상태를 저장해서 다시 쓸 수 있는가?”를 보면 된다.
> 
> 중복 부분 문제:
> 
> ```text
> fib(5)
> = fib(4) + fib(3)
> = fib(3) + fib(2) + fib(3)
> ```
> 
> `fib(3)`처럼 같은 계산이 반복된다.  
> 이 값을 저장해두면 다시 계산하지 않아도 된다.
> 
> 최적 부분 구조:
> 
> ```text
> dp[i] = i번째까지의 최댓값
> dp[i] = max(dp[i-1], dp[i-2] + 현재값)
> ```
> 
> 현재 최적해를 이전 최적해들로 만들 수 있다.
> 
> 경우의 수 구조:
> 
> ```text
> 길이 n을 만드는 방법
> = 마지막에 1칸 붙이는 경우
> + 마지막에 2칸 붙이는 경우
> ```
> 
> 예:
> 
> ```java
> dp[i] = dp[i - 1] + dp[i - 2];
> ```

## 2. DP 사고과정

> [!tip]  
> DP는 점화식을 바로 세우려 하지 말고, `dp[i]의 의미`부터 정해야 한다.
> 
> ```text
> 1. 문제 유형 판단
>    경우의 수인가?
>    최댓값/최솟값인가?
>    가능 여부인가?
> 
> 2. dp 상태 정의
>    dp[i]가 무엇을 의미하는지 정한다
>    필요하면 dp[i][j]처럼 상태를 늘린다
> 
> 3. 마지막 선택 기준으로 경우 분류
>    마지막에 무엇을 선택했는가?
>    어디서 온 상태인가?
> 
> 4. 점화식 작성
>    경우의 수면 더한다
>    최댓값/최솟값이면 max/min 한다
>    가능 여부면 true/false로 갱신한다
> 
> 5. 초기값 설정
>    dp[0], dp[1], dp[2]처럼 작은 값은 직접 구한다
> 
> 6. 정답 위치 확인
>    마지막 값이 답인지, 전체 dp 중 최댓값이 답인지 확인한다
> ```
> 
> 점화식이 막히면 이렇게 생각한다.
> 
> ```text
> 마지막 선택이 무엇인가?
> 그 선택을 하기 직전 상태는 무엇인가?
> 이전 상태만으로 현재 상태를 표현할 수 있는가?
> 이전 정보가 부족하면 상태를 쪼개야 하는가?
> ```

## 3. 상태를 쪼개야 하는 경우

> [!warning]  
> `dp[i]` 하나로 이전 상황을 표현할 수 없으면 상태를 나눠야 한다.
> 
> 예를 들어 “빨간색은 연속 불가”라면 단순히 `dp[i]`만으로는 마지막 색이 무엇인지 알 수 없다.
> 
> 이럴 때:
> 
> ```text
> red[i] = i번째가 빨강으로 끝나는 경우
> blue[i] = i번째가 파랑으로 끝나는 경우
> yellow[i] = i번째가 노랑으로 끝나는 경우
> ```
> 
> 또는:
> 
> ```text
> dp[i][0] = i번째에서 특정 상태 0
> dp[i][1] = i번째에서 특정 상태 1
> ```
> 
> 상태를 쪼개야 하는 대표 상황:
> 
> |조건|상태 예시|
> |---|---|
> |이전 색과 달라야 함|마지막 색|
> |연속 선택 제한|연속 선택 횟수|
> |현재 위치와 비용 필요|`dp[i][cost]`|
> |두 문자열 비교|`dp[i][j]`|
> |무게 제한|`dp[i][w]` 또는 `dp[w]`|

## 4. 기본 코드 형태

> [!info]  
> Bottom-Up 방식은 작은 값부터 채워간다.  
> 코딩테스트에서는 재귀보다 반복문 DP가 더 안전한 경우가 많다.
> 
> 1차원 DP:
> 
> ```java
> int[] dp = new int[N + 1];
> 
> dp[0] = 1;
> dp[1] = 1;
> 
> for (int i = 2; i <= N; i++) {
>     dp[i] = dp[i - 1] + dp[i - 2];
> }
> ```
> 
> 2차원 DP:
> 
> ```java
> int[][] dp = new int[N + 1][M + 1];
> 
> for (int i = 1; i <= N; i++) {
>     for (int j = 1; j <= M; j++) {
>         dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
>     }
> }
> ```
> 
> Top-Down 방식은 재귀 + 메모이제이션이다.
> 
> ```java
> int[] memo = new int[N + 1];
> 
> int solve(int n) {
>     if (n <= 1) return n;
>     if (memo[n] != 0) return memo[n];
> 
>     return memo[n] = solve(n - 1) + solve(n - 2);
> }
> ```

## 5. 주의점

> [!warning]  
> DP에서 자주 틀리는 부분은 점화식보다 `상태 정의`, `초기값`, `정답 위치`다.
> 
> |실수|주의|
> |---|---|
> |dp 의미가 불명확함|`dp[i]`가 정확히 무엇인지 먼저 정의|
> |초기값 누락|작은 n은 직접 계산|
> |음수 인덱스 접근|`i-2`, `i-3` 조심|
> |상태 부족|이전 색, 연속 횟수 등이 필요하면 상태 분리|
> |정답 위치 착각|항상 `dp[N]`이 답은 아님|
> |재귀 깊이 초과|깊으면 Bottom-Up 고려|
> 
> DP 문제를 만나면 먼저 아래 문장을 채운다.
> 
> ```text
> dp[i]는 ________ 를 의미한다.
> dp[i]는 ________ 경우에서 온다.
> 초기값은 ________ 이다.
> 정답은 ________ 에 있다.
> ```

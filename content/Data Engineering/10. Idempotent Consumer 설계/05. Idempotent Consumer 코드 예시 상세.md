## 개요

idempotent consumer 코드는 message id 저장, 업무 변경, offset ack 순서를 명시해야 한다.

이 문서는 `Idempotent Consumer 설계` 챕터 안에서 `Idempotent Consumer 코드 예시` 주제를 백엔드 서비스 데이터 흐름의 일부로 정리한다. 중요한 것은 구현 API 이름이 아니라 source, event, processor, target, quality check가 어떤 계약으로 이어지는지다.

기준 상황은 결제 완료 이벤트 consumer가 DB 저장 후 offset commit 전에 죽어 재시작 후 같은 포인트 지급을 다시 수행할 수 있는 상황이다. 이 상황에서 `Idempotent Consumer 코드 예시` 주제를 제대로 설계하지 않으면 API는 정상이어도 downstream 데이터가 늦거나, 중복되거나, 누락되거나, 잘못된 지표로 사용될 수 있다.

## 원리

- `Idempotent Consumer 코드 예시` 관점: message id를 처리 이력에 먼저 기록하거나 같은 transaction에 묶는다.
- `Idempotent Consumer 코드 예시` 관점: 업무 DB commit과 offset commit 순서를 명확히 한다.
- `Idempotent Consumer 코드 예시` 관점: 외부 side effect에는 provider idempotency key를 사용한다.
- `Idempotent Consumer 코드 예시` 관점: 중복 감지는 오류가 아니라 정상 branch로 다룬다.

이 원칙들은 모두 source, key, 처리 단위, 재처리 가능성으로 연결된다. `Idempotent Consumer 코드 예시` 문서를 읽을 때는 "어떤 데이터가 사실인가", "어느 단위부터 다시 처리할 수 있는가", "완료를 어떤 쿼리로 검증하는가"를 계속 확인한다.

## 판단 축

- message id를 처리 이력에 먼저 기록하거나 같은 transaction에 묶는다.
- 업무 DB commit과 offset commit 순서를 명확히 한다.
- 외부 side effect에는 provider idempotency key를 사용한다.
- 중복 감지는 오류가 아니라 정상 branch로 다룬다.
- 처리 이력 테이블의 보관 기간과 index를 관리한다.

리뷰에서는 처리 이력 insert와 업무 변경이 같은 실패 단위에 묶였는지 확인한다.

## 예시

```sql
CREATE TABLE processed_messages (
    consumer_name varchar(100) NOT NULL,
    message_id varchar(120) NOT NULL,
    processed_at timestamp NOT NULL DEFAULT now(),
    PRIMARY KEY (consumer_name, message_id)
);
```

```java
@Transactional
public void apply(OrderPaidEvent event) {
    if (!processedMessages.markIfFirst("point-consumer", event.eventId())) {
        return;
    }
    pointService.addPoint(event.memberId(), event.paidAmount() / 100);
}
```

예시는 하나의 정답이 아니다. 핵심은 `Idempotent Consumer 코드 예시`에서 처리 key, 상태 기록, 실패 보관, 재처리 범위가 코드나 SQL에 드러나야 한다는 점이다.

## 실패 모델

- `Idempotent Consumer 코드 예시` 실패 신호: message id 없이 payload hash로 중복을 판단한다.
- `Idempotent Consumer 코드 예시` 실패 신호: 처리 이력 insert와 업무 변경이 다른 transaction에 있다.
- `Idempotent Consumer 코드 예시` 실패 신호: offset commit 실패 후 재처리 시 side effect가 다시 실행된다.
- `Idempotent Consumer 코드 예시` 실패 신호: 외부 API가 멱등하지 않은데 재시도를 건다.
- `Idempotent Consumer 코드 예시` 복구 기준: transient failure는 제한된 retry와 backoff로 처리하고, permanent failure는 사람이 분류할 수 있는 위치에 남긴다.
- `Idempotent Consumer 코드 예시` 재처리 기준: 같은 입력을 다시 넣어도 결과가 안전한지 idempotency 또는 deduplication으로 확인한다.
- `Idempotent Consumer 코드 예시` 완료 기준: 처리 건수뿐 아니라 source와 target의 의미 있는 합계와 최신 시각을 비교한다.

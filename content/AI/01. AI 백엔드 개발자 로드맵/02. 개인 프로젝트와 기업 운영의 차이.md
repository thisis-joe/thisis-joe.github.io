>- 개인 프로젝트에서 어디까지 구현하면 실전 감각을 보여줄 수 있는가?
>- 기업 운영에서는 왜 같은 기능에도 더 많은 장치가 필요한가?
>- AI 기능의 성숙도를 단계별로 어떻게 올릴 수 있는가?

## 개요

개인 프로젝트와 기업 운영은 목표가 다르다. 개인 프로젝트는 학습과 증명, 빠른 실험이 중요하다. 기업 운영은 안정성, 보안, 비용, 감사, 팀 협업이 중요하다.

하지만 개인 프로젝트도 최소 운영 감각을 보여줄 수 있다. timeout, usage log, prompt version, eval set 같은 작은 장치가 그 차이를 만든다.

## 개인 프로젝트 최소 기준

개인 프로젝트에서 꼭 챙기면 좋은 것:

- API key를 환경 변수로 관리한다.
- 모델 호출 wrapper를 둔다.
- timeout을 둔다.
- schema validation을 한다.
- prompt version을 기록한다.
- token usage를 로그로 남긴다.
- 대표 질문 10개 정도의 eval set을 둔다.
- RAG라면 source id와 삭제 절차를 둔다.

이 정도만 있어도 단순 데모와 구분된다.

## 기업 운영 수준 기준

기업에서는 다음이 추가된다.

- tenant별 quota
- SLO와 alert
- provider 장애 런북
- fallback과 degrade mode
- prompt/model/schema 변경 승인
- eval regression gate
- 개인정보 처리 정책
- audit log
- 보안 threat model
- 인프라 용량 계획

기업은 사용자 수와 데이터 민감도가 크기 때문에 작은 실수의 피해가 커진다.

## 성숙도 단계

```text
Level 0: 데모
  모델 호출 성공

Level 1: 개인 프로젝트 최소 기준
  timeout, schema validation, prompt version, usage log

Level 2: MVP
  quota, source 표시, 작은 eval, 장애 메시지

Level 3: 사내 도구
  권한, audit log, human review, runbook

Level 4: 고객-facing 서비스
  SLO, fallback, CS trace, 보안 리뷰

Level 5: 기업 운영/규제 환경
  데이터 거버넌스, vendor risk, compliance, 정기 eval
```

## 코드로 이해하기

성숙도에 따라 설정도 달라진다.

```yaml
ai:
  feature: document-qa
  prompt_version: doc-qa-v1
  timeout_seconds: 8
  max_output_tokens: 800
  log_usage: true
  eval_dataset: small-regression.json
```

개인 프로젝트도 이런 설정을 명시하면 나중에 기업형 구조로 확장하기 쉽다.

## 인프라 협업 포인트

개인 프로젝트에서는 혼자 결정하지만, 기업에서는 인프라팀과 다음을 합의해야 한다.

- provider outbound
- secret 저장
- rate limit
- worker scaling
- vector DB 운영
- log retention
- trace sampling

AI 기능은 인프라팀에게 예측하기 어려운 workload를 준다. 백엔드는 예상 사용량과 제한 정책을 숫자로 설명해야 한다.

## 실전 팁

- 개인 프로젝트도 “실패하면 어떻게 되는지”를 README에 적는다.
- 기업 운영 기준을 처음부터 모두 구현하지 말고, 확장 가능한 경계를 먼저 둔다.
- MVP 단계에서는 기능 flag를 꼭 둔다.
- 고객-facing 단계에서는 CS가 trace와 source를 확인할 수 있어야 한다.

## 위험 신호!

- 개인 프로젝트라는 이유로 API key가 코드에 있다.
- MVP인데 비용 제한이 없다.
- 사내 도구인데 audit log가 없다.
- 고객-facing 서비스인데 fallback과 장애 문구가 없다.
- 기업 운영인데 prompt 변경 승인 절차가 없다.

## 확인 질문

- 개인 프로젝트에서 최소로 넣어야 할 운영 감각은 무엇인가?
	- timeout, schema validation, prompt version, usage log, 작은 eval set이다.
- 기업 운영에서 개인 프로젝트보다 추가되는 핵심 책임은 무엇인가?
	- SLO, 보안, 비용 예산, audit log, 장애 런북, 조직 협업이다.
